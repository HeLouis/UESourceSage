# Routing Protocol

## Normalize Input

Resolve the domain module, Build.cs-scoped submodule, intent (`orient`, `explain`, `trace`, `extend`, `diagnose`, `compare_version`, or `review`), anchor, depth, and engine version. Ask when the submodule cannot be selected without changing the source allowlist.

## Route Order

1. Select one domain with `modules/index.md`.
2. Select one submodule with its `submodules/index.md`; do not infer access from dependencies.
3. Read the domain and submodule routers, manifests, and small process states.
4. Search compact question indexes, submodule first and domain second.
5. Check constraints for combined requirements or diagnosis and ambiguity indexes for unclear symbols.
6. Select one intent row and one topic row.
7. Open up to the configured canonical-document budget, preferring submodule documents.
8. Use guarded source read/search commands for only the required files and symbols.

## Boundaries

- Keep one domain and one submodule active.
- Files from another Build.cs source directory are prohibited. Activate or create its separate submodule instead of adding it to the current submodule.
- A domain-level comparison may read rendered knowledge from multiple submodules, but it does not directly grant engine-source access. Inspect source under one active submodule at a time.
- Re-route and discard unrelated context when the active submodule changes.

## Reading Budget And Output

Read one domain route row, one submodule route row, one intent and topic/constraint row, up to three canonical documents by default, and the minimum allowlisted source files. Lead with the answer, state domain/submodule/version once, give an ordered source trail, and distinguish verified facts, inference, and unresolved questions. Do not dump indexes, internal routing narration, or large source blocks.
